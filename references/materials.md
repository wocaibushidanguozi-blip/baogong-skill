# 素材阶段

## 目标

根据一个已经完成的摘要，先锁定来源，再抓取能直接进入剪辑工程的素材包，优先解决两件事：

1. 给文案中的关键事实找到可展示的原始页面、评论原话或短视频片段。
2. 让剪辑时能快速知道每个素材放在哪里、证明什么、不能证明什么。

没有锁定原始材料时，不为了凑满素材包而下载泛相关视频。宁可输出“暂未锁定原始素材”，也不能用相似画面制造事实对应关系。

## 来源锁定流程

素材阶段必须按以下顺序执行：

```text
来源定位 -> 来源核验 -> 素材抓取
```

1. 来源定位：根据摘要中的原始标题、独特短语、作者、平台、日期和转述链寻找候选来源。
2. 来源核验：确认候选来源确实对应本期选题，至少核对作者/账号、平台、发布时间、原文或视频标题，以及选题关键句是否在内容中出现或被明确转述。
3. 素材抓取：只对核验通过的来源截图、下载或截取视频片段，并记录来源关系。

“主题相似”不等于“来源对应”。没有完成来源核验的内容不得进入核心素材区，也不得被旁白当作本期事件证据。

如果选题来自二手转述，必须先追踪：

```text
二手转述 -> 转述对象 -> 原始账号/页面 -> 原始视频或原帖
```

连续两轮追溯仍无法锁定原始来源时，停止扩展搜索，交付“来源未锁定”结果；不能改用语义相似视频凑数。

## 数量上限

每个选题最多保留 6 个核心素材和 2 个备用素材，总数不超过 8 个；这是上限，不是交付目标。抓取过程中最多保留 12 个候选素材；超过后只保留来源关系更强、画面更清楚、与文案对应更直接的版本。

一个原始视频最多切出 3 个片段。连续找到 3 条表达相同观点的评论后停止寻找同类截图。连续两轮追溯仍找不到原始材料时，记录为素材缺口并停止扩展搜索。

素材不足时保留缺口，不用泛相关画面填充。核心素材为 0 条也是有效结果。

## 素材类型

每个素材必须标记一种类型：

- `quote_screenshot`：评论、帖子、标题或公开声明的截图，保留账号名、发布时间、页面来源和必要上下文。
- `short_video`：原始视频或公开视频中的短片段，记录平台、视频 URL、起止时间和画面内容。
- `source_page`：原始页面、公告、采访或完整视频页面的截图/存档，用来证明来源链。
- `context_visual`：只帮助解释背景的图表、公开文件页面或环境画面，不能单独证明事件发生。

不制作额外的素材总览图。每张截图和每个视频片段都必须能从 `素材清单.md` 直接定位。

每个素材必须标记来源关系：

- `direct_source`：本期选题对应的原始视频、原帖、公开文件或当事人说明。
- `secondary_source`：明确转述本期原始内容的二手材料，必须保留转述边界。
- `related_discussion`：表达相似观点但未证明与本期来源有关，只能作为语境素材。
- `generic_visual`：泛相关画面，只能作为装饰或背景。

只有 `direct_source` 和经过核验的 `secondary_source` 可以进入核心素材。`related_discussion` 和 `generic_visual` 必须放入 `context/`，不能计入核心素材数量。

## 抓取顺序

1. 读取摘要中的“已确认事实”和“来源列表”，为每个事实建立素材需求。
2. 优先寻找原始视频、原帖、当事人公开说明、公开文件和完整页面。
3. 再寻找能直接呈现争议原话的评论或帖子截图；截图必须保留上下文，不能只截断言部分。
4. 对视频记录可用片段：起止时间、画面描述、原声是否可用、是否需要打码，以及它对应文案的哪一句。
5. 对无法访问、已删除、无法确认来源或只有相关推荐的内容，写入“素材缺口”，不下载替代品。

## 证据与剪辑边界

素材包必须区分：

```text
证据素材：可以支撑某个已确认事实或直接呈现原话
语境素材：可以帮助理解讨论背景，但不能单独支撑事实
装饰素材：只用于节奏和氛围，不得被旁白暗示为事实画面
```

旁白涉及具体事实时，优先使用证据素材或明确标注来源页面；旁白涉及栏目判断时，可以使用语境素材，但不能把语境画面剪成事件现场。未成年人、私人账号、电话号码、住址和其他敏感信息按需打码。

不绕过登录、验证码、付费墙、地区限制或平台技术限制。下载或截图只处理公开可访问内容，并保留原始 URL 和抓取日期。平台允许公开观看不等于可以无条件再发布，输出中记录版权/转载风险，最终发布由用户判断。

## 输出目录

默认在 `/Users/solaris/Desktop/工作/自媒体先锋/素材/<date>-<topic-slug>/` 保存：

- `素材清单.md`：唯一正式的素材清单，按文案顺序列出推荐使用的素材。
- `screenshots/`：原话和来源页面截图。
- `clips/`：可用短视频片段或原视频定位信息。
- `context/`：未锁定来源的相关讨论或泛相关画面，不得作为事实证据。

可按需要增加：

- `raw/`：公开可访问的原始下载文件，保留原文件名或来源标识。
- `context/`：辅助画面；不能将其中画面暗示为事件现场。

如果无法保存媒体文件，仍然生成 `素材清单.md`，记录在线 URL、时间点和截图/下载失败原因。

不默认生成 Word 文档或素材总览图。用户明确需要打印、汇报或对外发送时，再从 `素材清单.md` 生成 Word 副本；`.md` 始终是唯一正式版本。

## 素材清单字段

```text
id
type
file_path
source_url
platform
source_relation
source_lock_status: locked / secondary_locked / unlocked
captured_at
source_published_at
evidence_level
supports_claim
cannot_prove
clip_start
clip_end
visual_description
audio_status
privacy_action
copyright_risk
recommended_script_line
status: ready / partial / missing
```

ID 只是索引，不能单独交付。每一项必须提供：

- 本地相对路径；如果无法保存，标记 `remote_only` 并提供在线 URL。
- 原始来源链接和抓取日期。
- `source_relation` 和 `source_lock_status`，说明它是原始来源、二手来源还是未锁定的相关内容。
- 截图保留账号名、发布时间和必要上下文；涉及未成年人和私人信息时打码。
- 视频片段的起止时间、画面描述、原声状态和对应文案。
- `supports_claim` 与 `cannot_prove`，说明素材能证明和不能证明什么。

文件名使用可直接搜索的格式，例如：

```text
S01-微博支持观点.png
S02-微博反方观点.png
S03-原始视频-00m12s-00m22s.mp4
S04-微博话题页.png
```

## 阶段门槛

- 摘要为 `排除`：不抓素材。
- 摘要为 `待核实`：只能定位和抓取“争议存在”或二手原话素材，不得把未确认事件细节做成事实画面。
- 摘要为 `条件通过`：先完成来源锁定；如果只有二手来源，必须在 `素材清单.md` 开头注明“没有单一原始事件素材”。
- 摘要为 `通过`：按已确认事实逐项锁定原始来源，再抓取证据素材。

## 最低交付标准

素材阶段结束时，至少输出：

1. 一份素材清单，逐项写明来源和证据边界。
2. 清晰的单张原话/来源页面截图和可直接剪辑的视频片段；如果没有，明确写“暂无可用核心素材”。
3. 一张“文案句子 → 素材 ID → 本地文件 → 使用方式”的映射表。
4. 一份素材缺口和下一步补抓列表。

如果来源未锁定，最低交付只需要清单和缺口说明，不要求凑出 6 条素材。
